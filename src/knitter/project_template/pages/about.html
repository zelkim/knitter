Get Started with Knitter

This boilerplate site was generated by Knitter, a small static site generator that stitches together Jinja templates, JSON data, and SCSS into static HTML. Everything you see here is wired up through one configuration file: knitter.toml.

How this boilerplate is wired

The root knitter.toml file tells Knitter how to build this project:

  • [assets_folder] – points to the folder that will be copied into dist/assets/. In this boilerplate, that is the assets/ directory.
  • [processed_files] – maps output CSS files to their SCSS sources. Here, css/main.css is compiled from src/scss/main.scss and written into dist/assets/css/main.css.
  • [routes] – maps URL paths to Jinja templates under pages/. For example, "/" renders the landing page and "/about" renders this page.
  • [data] – lists JSON files that should be loaded and exposed to templates. In this project, data/landing-locales.json becomes the landing_locales variable used by the landing layout.

During a build, Knitter reads knitter.toml, loads any configured JSON data, renders the templates for each route with that data, compiles SCSS using the sass executable, and then writes everything into a dist/ folder ready to deploy.

The three core commands

knitter init <directory>

Use knitter init to create this exact boilerplate in a directory you choose. Knitter copies a starter project (including knitter.toml, pages/, src/scss/, assets/, and sample data) into the target folder without overwriting existing files. This is the quickest way to spin up a new site based on the same structure you see here.

Example:
knitter init my-site

knitter build

Run knitter build from your project root to generate a production-ready version of your site in dist/. Knitter will:

  • Render all routes defined in knitter.toml into dist/<route>/index.html.
  • Compile SCSS files listed under [processed_files] using Dart Sass.
  • Minify the compiled CSS for smaller payloads.
  • Copy everything from your assets folder into dist/assets/.

knitter serve

Use knitter serve while you are developing. Knitter will first build the site, then start a local server (by default at http://localhost:2016) and watch your templates, SCSS, data files, and assets for changes. When a file changes, Knitter rebuilds and the browser reloads automatically.

From here, you can customize the templates under pages/, tweak src/scss/main.scss, and add your own JSON data files under data/—all driven by updates to knitter.toml.
